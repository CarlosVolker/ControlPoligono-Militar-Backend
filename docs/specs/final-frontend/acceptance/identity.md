## Convenciones de familia

- **Precondición base (toda fila):** sesión real activa con tenant y unidad activa
  resueltos; personas, puestos y memberships **reales** del scope (tenant+rama). Si el
  dato necesario no existe (p. ej. usuario con assignment secundaria para quitar), el
  criterio queda pendiente por falta de dato real: fixtures, mocks y cuentas sintéticas
  están prohibidos; ningún ejemplo usa PII real (placeholders `<RUT>`, `{id}`).
- **Fallos heredados:** `F-01…F-12` y `ST-*` según perfil `P-*`
  ([`../experience/states.md`](../experience/states.md) §Mapa); la columna de fallos
  registra sólo deltas. `PUT`/`PATCH` comparten editor/modal pero son criterios
  separados (delta: envío completo vs parcial).
- **Regla de autoridad:** la UI anticipa visibilidad con `context.permissions`, pero
  sólo el backend decide; un `403` es denegación visible (ST-07), nunca dato vacío.
  Las mutaciones que afectan acceso o credenciales exigen ST-10 (R-RES-24 vía perfil).
- **Selectores reales:** unidad (OP-AZC-004/OP-UNT-010), rol por categoría (OP-AZC-002),
  scope (OP-SCP-001), personas (OP-USR-001/OP-AZC-003): ningún selector se llena de
  memoria (R-SES-009).
